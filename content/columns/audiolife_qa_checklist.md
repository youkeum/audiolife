# AudioLife 컬럼 QA 체크리스트 (100일 프로젝트 기준)

이 문서는 현재 AudioLife 컬럼 운영 방식에 맞춘 수동 점검 기준입니다.
자동 점검 스크립트(`/Users/ykkim/Desktop/Homepage/content/columns/content_qa.py`)와 함께 사용하세요.

## 0) 권장 점검 순서

1. 자동 점검 실행
2. 수동 체크리스트 점검
3. 빌드 검증
4. 최종 게시

권장 명령어:

```bash
python3 /Users/ykkim/Desktop/Homepage/content/columns/content_qa.py /Users/ykkim/Desktop/Homepage/content/columns/posts/hifi-headfi-100days-dayN.md
npm run build
```

## 1) Front Matter / 메타데이터

- [ ] 프론트매터 블록(`---`)이 문서 맨 앞에 존재한다.
- [ ] 필수 키 `title`, `date`, `excerpt`, `category`, `tags`가 모두 있다.
- [ ] 날짜 형식이 `YYYY-MM-DD`다.
- [ ] 파일명에 공백이 없고 slug 규칙에 맞는다.
- [ ] `excerpt`가 1~2문장으로 핵심을 요약한다.
- [ ] `category: "COLUMN"` 및 태그 구성이 기존 정책과 일치한다.

## 2) 100일 프로젝트 고정 구조

- [ ] 아래 H2 섹션 순서를 유지한다.
  - `오늘의 질문`
  - `핵심 개념 3개`
  - `공학적으로 이해하기`
  - `청취 경험/인문학적 관점`
  - `실전 예시`
  - `앞으로의 학습 흐름`
  - `마무리`
- [ ] 당일 Day 범위를 넘는 심화 내용은 소개 수준으로만 언급했다.
- [ ] 이전/다음 Day 연결 문장이 본문에 자연스럽게 들어가 있다.

## 3) 내용 품질

- [ ] 핵심 용어는 첫 등장 시 짧게 정의했다.
- [ ] 공학적 설명과 주관적 견해가 섞이지 않고 구분된다.
- [ ] 과장/단정 표현보다 조건부 판단 기준 중심으로 서술했다.
- [ ] 수치/공식/단위 표기가 앞뒤 문맥과 일관된다.
- [ ] 주장이 근거(원리, 조건, 사례)와 함께 제시된다.

## 4) 실전 예시 품질

- [ ] 예시가 당일 주제와 1:1로 직접 연결된다.
- [ ] 예시는 `상황 -> 문제 -> 원인 -> 점검 -> 결론` 흐름을 따른다.
- [ ] 최소 1개 이상의 구체 조건(레벨, 포맷, 세팅, 환경)이 포함된다.
- [ ] 독자가 바로 적용할 수 있는 행동 지침이 있다.

## 5) 이미지 / 미디어

- [ ] 커버 1장 + 인서트 3장(총 4장) 구성이 맞다.
- [ ] 이미지 경로가 실제 파일과 일치한다.
  - 예: `/posts/columns/36.png` <-> `/Users/ykkim/Desktop/Homepage/public/posts/columns/36.png`
- [ ] alt 텍스트가 비어 있지 않다.
- [ ] 4장의 역할이 분리되어 있다(커버/개념/메커니즘/예시).
- [ ] 이미지 톤이 `IMAGE_PROMPT_GUIDE.MD`와 일관된다.

## 6) 링크 / 기술 점검

- [ ] 본문 링크가 끊어지지 않았다.
- [ ] 루트 에셋 링크(`/posts/...`)가 실제 `public/` 파일과 매칭된다.
- [ ] 헤딩 레벨이 비정상적으로 점프하지 않는다.
- [ ] 지나치게 긴 문단은 분리했다.

## 7) 최종 승인 플로우 (권장)

- 1차 QA(자동): Codex 실행 + 리포트
- 2차 QA(수동): Codex 체크리스트 점검 및 수정 제안
- 최종 승인: 작성자(당신) 판단 후 확정

즉, 실무적으로는 **Codex가 1·2차 점검을 수행하고**,
**최종 발행 결정은 작성자(당신)가 하는 구조**가 가장 안정적입니다.
